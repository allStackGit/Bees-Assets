# Performance Ledger

Static-only audit; no runtime measurements are claimed. This ledger contains unresolved validated optimization opportunities only.

1. **PERF-037 — Ship combat teardown and target reacquisition still allocate pooled/runtime collections.** `Scripts/Entities/Ships/Ship.Combat.cs` snapshots `WeaponsThatHaveUsWithinRange`, allocates side-filtered ship lists during Carrier cleanup, and replaces `Command.OriginalQueue`/`TargetingQueue` when targets are exhausted. Reuse existing command queues, scan authoritative ship collections directly, and avoid unnecessary death snapshots. `FireBarge`/`Carrier` overrides must preserve their special teardown semantics.
2. **PERF-047 — Mining rebuilds a pooled ship list and repeatedly restates a stationary route.** `Scripts/Levels/Commands/Mining.cs/Execute()` replaces `MiningShips` with a LINQ `ToList()`, while `Timer()` repeatedly calls `SetAndMove()` toward the same stationary asteroid. Refill the command-owned list in place and issue the static movement route once while retaining liveness/completion monitoring.
3. **PERF-048 — Heal rebuilds pooled collections and can restart completed paths to stationary Beehives.** `Scripts/Levels/Commands/Heal.cs/Execute()` materializes `TargetBeehives` and a new ordered `Queue<Ship>` each command. `MoveToBeehives()` calls `MoveToPoint()` after A* has completed even when a useful path is still being followed. Reuse command-owned buffers/queue and use tracked movement ownership for Beehive approach.
4. **PERF-049 — Ship-clearance setup repeatedly filters and copies the live ship list.** `Scripts/Levels/Level.Environment.cs/CalculateShipClearances()` rebuilds `_clearance_Ships` with `Where(...).ToList()` once per ship type. Scan live ships once, reuse `Stage.ShipClearances`, and assign cached/computed clearance directly.
5. **PERF-050 — The recurring socket resend poll allocates a StandingRequests snapshot.** `Scripts/Server/Socket.cs/CheckForResends()` calls `StandingRequests.ToList()` every one-second poll. Rebuild a persistent snapshot buffer instead. `GetStandingRequest()` also uses a LINQ predicate for every response; use a direct set scan without introducing a mutable-hash index.
6. **PERF-051 — Special-ship death paths allocate side-filtered collections.** `Scripts/Entities/Ships/Carrier.cs` builds multiple LINQ side lists while reassigning carrier ships, and `Scripts/Entities/Ships/WarpGate.cs` allocates a human-side list plus LINQ count to detect the final gate. Scan `Level.State.Ships` directly while preserving replacement/last-position semantics.
7. **PERF-052 — Repeated level setup materializes avoidable selection lists.** `Scripts/Levels/Level.Reset.cs` builds a LINQ list of possible random levels on every reset and `SelectFirstSquad()` allocates both side squad lists before checking `Stage.IsTraining`. Refill the existing possible-level buffer and put the training guard first/use direct squad lookup. `Stage.SetConfigOptionsAndOverrides()` also recreates ship-type lists during per-level setup where existing lists can be refilled safely.
8. **PERF-053 — Collision-asteroid breakup allocates shard-family sets and a death snapshot.** `Scripts/Entities/CollisionAsteroid.cs` replaces each pooled shard's already-owned `ShardFamily` with a new `HashSet` during breakup and snapshots `NearbyShips` with `ToList()` during death. Clear/refill each shard's persistent set and iterate the non-mutated nearby-ship set directly.
