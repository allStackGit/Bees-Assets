# Performance Ledger

Static-only audit; no runtime measurements are claimed. This ledger contains unresolved validated optimization opportunities only.

1. **PERF-050 — Socket response/auth paths still allocate transient request collections.** The production one-second resend poll now reuses a Scene-owned snapshot, but `Scripts/Server/Socket.cs/GetStandingRequest()` still uses the capturing predicate `StandingRequests.FirstOrDefault(r => r.Hash == hash)` on response handling. Authentication refresh/reconnect methods also materialize `StandingRequests.ToList()` snapshots, and direct `Socket.CheckForResends()` callers still replace `_standingRequests`. Replace the hash lookup with a direct set scan and reuse request snapshot storage where mutation safety is required.
2. **PERF-052 — Repeated episode setup still recreates random-spawn and formation collections.** Stage ship-type lists now reuse persistent buffers through `StageConfigOptions.Apply`, but `LevelConstructor.AddRandomSquads()` still creates a temporary `List<SavedSquad>` for each setup option and recomputes visible armed-type availability with LINQ inside the per-squad loop. `LevelConstructor.SpawnShipsAndSquads()` also creates setup/carrier/filtered-ship lists each invocation, while `Squad.PlaceFormationSlotsIndividually()` allocates a tuple list and `SetStartingPosition()` uses a capturing `List.ForEach` callback. Reuse setup buffers and direct loops without changing spawn, carrier, or formation semantics.
3. **PERF-055 — Socket strategic command responses still allocate sorting/materialization pipelines for target discovery.** GameState side-indexing now makes `GetHumanShips()`/`GetBeeShips()` allocation-free, but `Scripts/Server/Socket.cs/HandleStrategicCommandResponse()` still runs `Where(...).OrderBy(...).FirstOrDefault()` to select the nearest Warp Gate and `Where(...).Select(...).OrderBy(...).ToList()` to build Heal Beehive candidates. Use direct nearest selection for Warp Gates and refill/sort the existing `_beehives` buffer for Heal.
4. **PERF-056 — BombingRun still builds a diagnostic status string in its recurring timer during training.** Most hot command timers now skip `Squad.Status` interpolation when `Stage.IsTraining`, but `Scripts/Levels/Commands/BombingRun.cs/Timer()` still assigns `GetSquad().Status = $"In the middle of bombing run..."` every 0.25–2 seconds. `Squad.Status` is observational/debug state, so guard that recurring assignment in training while preserving rendered/debug behavior.
