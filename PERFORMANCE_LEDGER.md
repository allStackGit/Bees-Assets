# Performance Ledger

Static-only audit; no runtime measurements are claimed. This ledger contains unresolved validated optimization opportunities only.

1. **PERF-050 — Socket response/auth paths still allocate transient request collections.** The production one-second resend poll now reuses a Scene-owned snapshot, but `Scripts/Server/Socket.cs/GetStandingRequest()` still uses the capturing predicate `StandingRequests.FirstOrDefault(r => r.Hash == hash)` on response handling. Authentication refresh/reconnect methods also materialize `StandingRequests.ToList()` snapshots, and direct `Socket.CheckForResends()` callers still replace `_standingRequests`. Replace the hash lookup with a direct set scan and reuse request snapshot storage where mutation safety is required.
2. **PERF-052 — Repeated level generation still recreates setup collections.** `Level.Reset` now reuses random-level candidates and `Level.Setup` assigns clearances in one pass, but `Stage.SetConfigOptionsAndOverrides()` still replaces `BeeShipTypes`/`HumanShipTypes` with `ToList()` or singleton lists on each level setup. `LevelConstructor.AddRandomSquads()` also creates temporary squad lists each episode and recomputes visible armed-type availability inside the per-squad loop. Refill persistent setup buffers and precompute invariant side/type availability.
3. **PERF-055 — Socket strategic command responses materialize side lists and sorting pipelines for target discovery.** `Scripts/Server/Socket.cs/HandleStrategicCommandResponse()` builds and sorts `GetHumanShips()` to select the nearest Warp Gate for Full Retreat and builds `GetBeeShips().Where(...).Select(...).OrderBy(...).ToList()` for Heal. Use direct nearest selection for Warp Gates and refill/sort the existing `_beehives` buffer for Heal.
