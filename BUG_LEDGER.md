# Bug Ledger

Static-only repository audit on `rl/initial-design-work`. This ledger tracks validated, unresolved defects for the active audit; fixed regressions belong in `docs/engineering/REGRESSIONS.md`.

The WAN actor empty-trajectory-queue crash and capped training-log flush stall were fixed. A stale duplicate-acknowledgement race found in both fixed-topology and elastic brokers was fixed, with focused regression protection added. Invalid numeric matchup-mode values were fixed to accept only the named modes. No tests were executed, per the audit's static-only constraint. The initial episode-log scan now preserves a complete first record when its 4 MiB tail begins on a line boundary, with focused regression coverage added. Elastic actor shutdown now joins its claim keeper so a delayed renewal cannot race the next session's slot claim; focused regression coverage was added. A same-build rollout can no longer count a worker whose active environment-argument identity differs from the pending configuration; focused regression coverage was added. A Titania failure warning is rebuilt idempotently when campaign overrides are reapplied; focused source-level regression coverage was added. A persistent campaign dialogue guard now prunes destroyed CutsceneManager keys after scene unload to avoid retaining per-scene dialogue data. WAN actor close now waits for started watcher/uploader threads before a replacement session can reuse its actor identity and output paths. BeesServer supervisor health results are bound to the probed child so late checks cannot affect a replacement process. Managed-worker restart backoff now resets when any launch-defining identity changes, including environment args and the state file, instead of treating only the command line as identity; regression cases were added but not run. The Pluto II “ships’ range” tooltip fix now uses a word boundary so the per-frame correction cannot append another “s” to its own pluralized output. The automatic telemetry watcher now rejects non-finite polling intervals to prevent its refresh thread from failing or blocking indefinitely; parser regression coverage was added but not run. Continual service checkpoint resumes are now bound to a persisted trainer-code/config/build/environment fingerprint; changes to production Python runtime sources, dependency manifests, or the configured Python executable, or changed or unverifiable lineages, require a new run ID, with regression coverage added but not run. Normal socket request history is now bounded to recent command/matchup requests during ordinary play, while explicit request-watch mode retains full diagnostic history.

The distributed launcher now rejects worker topologies whose allocated TCP ports exceed 65535, with boundary regression coverage added but not run. Remote rollout workers now reject control-environment arguments that differ from the hashed session spec, with regression coverage added but not run. The batched ML-Agents step loop now preserves healthy-worker results when a peer exits during response draining; regression coverage was added but not run. Finding passes: 0 / 2 consecutive clean full-code passes after the latest production fix. The repository-wide audit remains in progress; no full-pass completion is claimed. A further static audit found that a shared control-plane revision change could clear a dedicated worker's crash-loop backoff without changing its launch; the worker now retains backoff across revision-only updates, with a regression case added but not run (REG-038). A socket audit also found that an unknown successful matchup-strategy name indexed the enum map directly and could abort response handling after retiring the request; the client now falls back to Random with outcome ID 0 so the unrecognized server outcome is not credited to the fallback.
