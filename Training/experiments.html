    Adjust Hub scheduling budget

    Use a smaller CPU/RAM budget than the machine's physical capacity to leave room for existing Bees training or other workloads. These are scheduling admission limits, not measured utilization, CPU pinning, or a guarantee that unmanaged workloads will stay within their share. Disarm native automation before changing them. Existing native jobs are not stopped or resized, and claimed capacity cannot be reduced away.

    Adjust Hub GPU scheduling budgets

    Limit how much of each GPU the Hub may admit while leaving capacity for independently running Bees or other software. Set hub_vram_mb (0 to nominal VRAM MiB) and hub_compute_pct (0–100); zero disables new Hub GPU placements on that device. The limits are advisory accounting, not memory or compute isolation. Exclusive GPU jobs need the full Hub device budget; cooperative shared GPU jobs can use smaller budgets where their trusted adapter permits sharing. Disarm automation and release outstanding GPU-bearing leases before changing these values. No running process is resized or stopped.

    Bind physical GPUs

    Connected Linux AMDGPU and Windows NVIDIA agents can bind registered logical GPU IDs to observed PCI addresses. Windows NVIDIA leases additionally pin the CUDA GPU UUID. Existing GPU leases must be released before rebinding. Hub admission budgets for existing logical GPU IDs are preserved; edit those in the separate budget form. A Windows CUDA launch requires explicit local opt-in and a trusted CUDA adapter; the Job Object enforces CPU/RAM but cannot isolate or quota a GPU.

    Checkpoint evaluations · What can this network do?

    At each curriculum checkpoint, the saved network fights three fixed opponents, 100 matches each. The opponents and test conditions stay the same across beta runs. These matches measure ability; they do not train the network.

    Compare checkpoints and beta runs

    Compare the same test and stage across beta runs. Compare one network's earlier and later checkpoints to check learning and retention. A changed Unity build, opponent or benchmark recipe is a different test, even if the name is the same.
